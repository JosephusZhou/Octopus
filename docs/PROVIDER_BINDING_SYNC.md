# 供应商绑定和模型同步

## 使用方式

- 在供应商管理中保存模型列表，别名非空时作为可调用模型 ID，不做请求中的别名转换。
- Claude/Codex 环境通过供应商 ID 绑定。默认或独立档位模型被删除后回退到来源列表第一项；空列表清除模型设置。
- OpenCode、Pi、Oh-My-Pi、OmO 添加供应商时选择已有供应商或路由聚合，保存会批量导入模型并建立绑定。
- 绑定的 Agent 模型列表由来源管理；可编辑已存在模型的参数。需要独立增删模型时先解绑，解绑保留当前配置。
- 路由绑定按协议取模型集合。供应商模型为空时不再作为任意模型兜底；停用监听服务不会清空模型集合。
- 删除供应商时确认关联影响。环境及其他用户文件保留；关联 Agent 供应商块、环境连接和模型清除。部分清理失败时供应商先退出可用列表，后台继续重试。

## 持久化和重试

绑定存在 Octopus 的 `agents.db`，不添加到 Agent 原生配置 schema。
`provider_sync_state` 仅保存来源 ID、待删除/同步状态、错误及重试时间，不保存明文凭据或配置快照。
后台每 30 秒检查待处理来源，失败退避到最多 5 分钟。供应商管理页可查看失败原因并立即重试。
旧配置首次处理按协议对应地址唯一匹配；有多个历史绑定的目标不猜选。明确解绑后的目标记录已处理，不自动重新绑定。

同步不主动获取远端模型。新增模型只用本地 Models.dev 缓存（内存缓存优先，其次磁盘缓存），
补全规则与模型编辑弹窗的「从 Models.dev 补全」按钮完全一致：目录里同名模型常出现在十几家
provider 下，其中聚合入口往往不带 limit/模态数据，因此身份字段（名称、reasoning、tools）取
严格匹配该 provider 的条目，上下文/输入/输出上限与模态取所有命中的并集（第一个非空生效）。
目录没有的数据不编造，缺失时只写入最小默认值，需要使用者核对。

已经导入过的模型不会被自动回填：同步只保证「模型增删跟随来源」，已存在条目视为用户已有配置。
若某次导入时目录缓存还没准备好，可在模型编辑弹窗点「从 Models.dev 补全」手动补齐。
磁盘配置更新不代表运行中的外部 Agent 已热重载，必要时重启 Agent。

## 开发入口

- `provider_sync.rs`：来源解析、批量同步、默认槽位修复、地址迁移。
- `db.rs`：绑定唯一目标替换事务、来源保存与待同步状态事务、清理和重试状态。
- 各 Agent 后端：保留原始节点字段并一次性更新模型集合。
- `providerSource.ts`：不含凭据的来源候选读取与 Tauri 事件订阅。

## 同步恢复和冲突保护

首次 Agent 绑定先将来源、目标和不含凭据的写入意图一起提交到数据库，再写原生配置。
进程在两步之间退出时，下次启动根据最新来源重新执行，明确解绑会取消待执行意图。
模型文件和凭据文件分别记录成功/失败状态；部分成功后可重复执行，内容未变的已完成文件不重写。
删除重试即使发现供应商块已经删除，也会继续清理该块的凭据和默认槽位。

同步读取时在内存记录文件指纹，写入临时文件后、替换前再次检查。遇到外部变化重新读取并合并，最多尝试三次；持续冲突保留外部文件并报告失败，不强行覆盖。
文件指纹、原文件内容与明文凭据不会进入恢复记录。
旧配置迁移逐目标隔离，一个坏文件不会阻止其他环境或 Agent 绑定；失败和多来源歧义可在供应商管理页查看。

## 仍需验收和完善

多个文件的更新不是跨文件事务；恢复通过幂等重试完成，不撤回已成功的文件。
其他进程不受 App 写锁约束。替换前的检查可发现读改写期间的变化，但不能承诺跨进程完全原子比较与替换；对方恰在最后检查与 rename 之间写入仍存在很小的竞争窗口。
备份恢复后严格读取路由设置并刷新全部协议供应商池；地址不变时原地更新认证和行为，地址改变时重启原本运行的服务，原本停止的服务保持停止。新端口被占用时保留恢复设置、显示服务未启动及警告，不继续使用旧监听器。
前端已使用统一请求检查：切换 Agent、弹窗关闭、供应商切换、地址或凭据编辑时，使旧请求失效；旧成功、旧失败和旧 finally 都不能回填新界面。供应商读取失败保留原绑定，不自动退成远端拉取。绑定连接字段只读，需先明确改成手动配置。

## 自动化验证

```bash
pnpm test:web                # Node 单测 + 组件测试（真实 @tauri-apps/api + IPC shim）
pnpm exec vitest run         # 仅组件测试
node --test src/lib/latestRequest.test.mjs   # 请求防护单元测
cargo test --manifest-path src-tauri/Cargo.toml --lib provider_sync
cargo test --manifest-path src-tauri/Cargo.toml --lib config_sync_io
```

组件测试覆盖：四类 Agent 绑定列表禁止单独增删、保存携带供应商唯一 ID、来源变更事件移除已删除模型、
Claude/Codex 已绑定环境的模型候选只读 `get_provider_source_models`（请求计数为 0 次远端调用）、
来源读取失败不静默解绑、晚返回的密钥不覆盖用户输入、删除供应商前展示影响范围。
仍需在真实 macOS/Windows 应用中手测界面观感与窗口行为；自动化测试环境无法执行 GUI 验收。
